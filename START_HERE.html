How it works

Ten steps, two of them people. Seven build the client brief; the account lead signs it before any creative work starts; the creative draft follows; and a named creative lead approves the exact files before any creative leaves as a package. The runner owns sequence and refusal; deterministic gates verify every model output.

  1. 1 Readiness gate refuses to draft on thin input
  2. 2 Classification project type + sensitivity tier
  3. 3 Fidelity check garbled transcripts flagged, never fixed
  4. 4 Extraction no verbatim quote → no claim; a second reader checks it
  5. 5 Conflict pass disagreements surfaced, never resolved
  6. 6 Synthesis one canonical brief object
  7. 7 Render EL/EN generate once, render twice + review pages
  8. 8 Human sign-off not a system step — the gate it stops at
  9. 9 Creative draft only after sign-off; a draft until approved
  10. 10 Creative approval named creative lead; then a local package, never sent automatically

Every model step is verified by a deterministic gate: citations must resolve word-for-word, protected brand terms must survive, no figure may appear that no source stated. A failing output gets one repair attempt; then the system stops and says so.

Run it in five minutes

# tests need no model access — do this first
python3 -m venv .venv && source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m pytest -q                            # or: bash scripts/check.sh (tests + frozen grade + benchmark)

# the whole Stage-1 run offline, zero model calls (replays a wiring-fixture recording):
BRIEF_BUILDER_CLAUDE_BIN="$PWD/tools/replay/claude" python3 pipeline/runner.py --project fixtures/northlight_01 --out /tmp/bb-replay

# model stages run as Claude Code subagents — install + authenticate the claude CLI, then:
./demo.sh                                       # one document in, verified facts out,
                                                #   ends by opening its run view
python3 pipeline/runner.py --project fixtures/northlight_01   # full Stage-1 run → runs/<ts>/
python3 eval/harness.py runs/latest             # grade against the answer key
./run_full.sh                                   # background demo run — opens the finished brief

Every project folder carries a data_declaration.json (the fixtures declare synthetic); the runner refuses a folder without one (exit 6).

Python 3.9 or newer on macOS or Linux. The tests make no model calls; the model stages run on the owner's Claude account and their usage under the current routing is still being re-measured (the graded figures are from the earlier, Haiku-era routing).

Completed runs also copy their pages to reviews/ under recognisable names — that folder is the account team's shelf (see reviews/README.md for the sharing channels).

What the system will not do

Guess

Thin input is refused with a precise list of what to request from the client — a refusal is the product working.

Resolve conflicts

When sources disagree, both quotes are shown with citations. Resolution belongs to the account lead, by design.

Silently fix garbles

A mangled term is extracted as written and flagged for a person to confirm. (The graded run's renders dropped that flag — a documented defect, runs/tier3/KNOWN_DEFECTS.md B3.)

Invent figures

"Around eighty" stays that way until the client says eighty what. No number appears that no source stated.

Editorialise in views

The review pages are deterministic renders of the run's artifacts — they cannot say anything the artifacts do not say, and carry no run cost or model information.

Release creative on its own

Creative starts as a draft, on signed-off briefs only. It becomes a local delivery package only after a named creative lead approves the exact files; nothing is sent, posted or approved on anyone's behalf.

Since the graded run: the agency layer (Tiers 5–8)

The graded run is from July 2026. In September the pipeline gained the operating layer an agency needs around it — all local commands, run by people, with no model calls.

What it adds

Evidence-coverage audits and question triage; conflict resolution, bilingual attestation and sign-off by command, bound to the exact revision; creative registration, approval, release, verification and withdrawal; clarification packs; effort and rework records for the pilot scorecard.

Hardened in round 1 (Tier 8)

Runtime agents read only staged input copies, under an untrusted-content rule and deny rules (SECURITY.md); separation of duties and a hash-chained audit log (release_control verify-log); a data declaration on every project, refused without one (exit 6); retention inventory and purge; an evaluation record with known defects (EVAL_RECORD.md); offline replay (tools/replay) and one check script (scripts/check.sh).

What it proves

The software behaves as specified: at Tier 8, 948 deterministic tests pass, the frozen evidence still grades 17/17 and a synthetic fault-injection benchmark passes 12/12. This is a software rehearsal.

What it does not prove

Generative quality under the current routing, Greek register, review time, adoption or any time saved. Those need the re-baseline and the pilot.

The decision asked, and the risks

The decision paper (WALKTHROUGH.html, sheet 10) asks the sponsor for three things: approve a four-week pilot with live use in week 4 conditional on the retrospective results; re-measure usage and time under the current routing before week 1; and estimate costs, confirm capacity and terms, and record a spending ceiling before week 1. Creative delivery is in the pilot from week 1, under separation of duties.

Usage is not yet measured

Extraction moved to a larger model plus a second reader on 30 July; one leg measured about twice the graded tokens. The whole-brief figure awaits the re-baseline.

Exam-green is not lead-ready

The harder second fixture scored 15/17, then 16/17 after a re-roll, with errors no check sees. A person reviews every brief.

Refusals happen

Three of ten supervised single-document runs were refused on both attempts (Haiku-era). A refusal stops the run; it never ships a guess.

Terms and data

Commercial and data-processing terms are unresolved, and only synthetic data is permitted until the agency approves a data policy.
